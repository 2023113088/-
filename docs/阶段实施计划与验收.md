## 阶段 A — 框架与注册发现（约 2～4 学时）

**目标**：能讲清楚「为什么是微服务、服务如何被发现」，跑通最小闭环。

**范围**：

- 启动 `eureka-server`（8761），在 Eureka UI 中看到实例。
- 启动至少 **1 个**业务服务（建议先 `book-service`），注册名 `BOOK-SERVICE`。
- 各服务暴露 **Actuator** `health`（已为 K8s 探针预留 `management.endpoint.health.probes.enabled`）。

**验收清单**：

1. 浏览器打开 `http://localhost:8761`，能看到已注册服务列表。
2. `GET http://localhost:9002/actuator/health`（直连 book）返回 `{"status":"UP"}`。
3. 实验报告可写：服务名、Eureka 默认 Zone、实例续约概念（用自己的话 + 截图）。

**刻意不做**：网关、Feign、熔断（避免第一节课 cognitive overload）。

---

## 阶段 B — Feign、负载均衡、熔断（约 4～6 学时）

**目标**：掌握「同步式服务间调用」与失败隔离，能演示 **降级后行为**。

**范围**：

- 启动 `borrow-service`，通过 **OpenFeign** 调用 `book-service`。
- **负载均衡**：同一 `BOOK-SERVICE` 多实例（不同端口、同一 `spring.application.name`）注册到 Eureka，多次调用观察轮询（可在报告里写步骤：复制一份 book 进程改 `server.port`）。
- **熔断 / 降级**：停止所有 `book-service` 实例后，借阅接口返回 **503 + 明确业务文案**（由 `BookFeignFallbackFactory` 打出日志 + 业务层 `SERVICE_UNAVAILABLE`）。

**验收清单**：

1. 正常：网关或直连 `borrow-service` 能完成借书且库存减 1。
2. 停止 book：借书返回 503，日志中出现 `BookFeign 熔断/降级`。
3. 报告附：Feign 接口代码片段、`fallbackFactory` 类、`resilience4j` 关键配置（`borrow-service` 的 `application.yml`）。

**工业级补充（已实现）**：

- Feign 出站 **透传 `X-Trace-Id`**（`BorrowOutboundFeignConfig`），与网关入口一致，便于联调。

## 阶段 C — API 网关：路由 + 认证（约 4～6 学时）

**目标**：所有对外流量经 **8080**，由网关统一 **JWT 校验** 与 **路由**。

**范围**：

- `gateway-service`：`lb://USER-SERVICE` / `lb://BOOK-SERVICE` / `lb://BORROW-SERVICE`。
- **白名单**：注册、登录、图书 GET 浏览（与教学演示平衡，可在报告说明安全权衡）。
- **JWT**：网关校验后注入 `X-User-Id`，借阅服务只信任网关内网（实验环境假设；生产应加 mTLS / 内部 Token）。

**验收清单**：

1. 无 Token 访问受保护接口 → `401`。
2. 登录拿 Token → 访问借阅成功；响应头带 **`X-Trace-Id`**（全链路排障）。
3. 报告画一张「客户端 → Gateway → 业务服务」的简图。

**工业级补充（已实现）**：

- **RFC 7807** `ProblemDetail` 统一错误（`library-common`）。
- **Bean Validation**（`@Valid`）与参数错误 400。
- **springdoc**：各业务服务 `http://localhost:9xxx/swagger-ui.html`（直连端口；网关聚合可列为阶段 D 任务）。

## 环境隔离（当前做到哪一步、还没做到哪一步）

**已经做的（真实隔离边界）**

| 层级 | 做法 |
|------|------|
| Spring | **默认 `application.yml`**：本机 IDE + **H2 内存库**；**`docker` profile** 走 **`application-docker.yml`** + **MySQL 独立三库**（userdb / bookdb / borrowdb），与宿主机其它项目数据库逻辑分离。 |
| Docker | **Compose 项目名** `library-cloud`、**独立桥接网络** `library-cloud-backend`、**命名数据卷** `library-cloud-mysql-data`，避免与宿主机其它 compose 栈的 default 网络/匿名卷混在一起。 |
| PPT 入口 | **Nginx**（`18888`）→ **Gateway**（`8080` 内网）；与课程图「前端 → Nginx → 网关」一致。 |
| PPT 配置中心 | **Spring Cloud Config**（`CONFIG-SERVER`），构建镜像时在容器内对 **`config-repo`** 执行 `git init` 并提交，Config 以 **`file:///git-config`** 读本地 Git，模拟「从 Git 拉配置」；各服务 **`spring.config.import`** 指向 `http://config-server:8888`。 |
| 密钥与配置 | **`env.example`** 列出变量；**`.gitignore` 忽略 `.env`**；compose 使用 **`${VAR:-默认值}`**；敏感项仍优先由 **compose 环境变量** 注入（未写入 `config-repo`）。 |
| 宿主机端口 | 网关/Eureka/各服务/MySQL 的**宿主机端口**均可通过 `.env` 覆盖（如 `GATEWAY_HOST_PORT`）；与其它项目 **只有「端口被占用」这一类冲突**，改 `.env` 即可，**不必改代码**。 |
| 服务间 | **内部令牌** `INTERNAL_SERVICE_TOKEN` 与 **用户 JWT** `APP_JWT_SECRET` 职责分离；库存接口与对外 REST 分离。 |

**尚未做 / 需要你们按实验阶段再上的（避免一次吹满）**

- **K8s Namespace / NetworkPolicy / ResourceQuota**：真正生产级多租户隔离在下一阶段（指导书 K8s 部分）。
- **微服务端口映射到宿主机**（9001–9003）仍暴露，便于调试 Swagger；若要做「仅网关出口」，可去掉各 `ports` 只保留 **8080**（或 8761 仅内网）。
- **业务库账号密码**若改 `MYSQL_PASSWORD`，须同步修改 **`docker/mysql/init/01-databases.sql`** 里 `CREATE USER ... IDENTIFIED BY`，否则首次初始化会不一致（init 脚本不支持读 `.env`）。

## 与课程 PPT 架构对齐（前端→Nginx→Gateway→消费者/提供者）

- **Nginx**：`library-nginx`，宿主机 **`${NGINX_HOST_PORT:-18888}`** → 反代到 **`gateway-service:8080`**（与 PPT「API 经 Nginx 进网关」一致）。调试也可直连网关端口 **`${GATEWAY_HOST_PORT:-8080}`**。
- **Spring Cloud Config**：`CONFIG-SERVER`（端口 **8888**），镜像构建时把 **`config-repo/`** 打成 **本地 Git 仓库**（`file:///git-config`），模拟 PPT「Config 从 Git 拉配置」；各业务与网关在 **`application-docker.yml`** 中 **`spring.config.import=optional:configserver:http://config-server:8888/`** 拉取合并配置（`optional` 避免本地未起 Config 时硬失败）。
- **Git 仓库目录**：`library-cloud/config-repo/`（提交记录由 **config-server 镜像构建** 内 `git init` 生成；你可继续往该目录加 yml 后重建镜像）。

## 全栈 Docker 运行（MySQL 持久化 + 真实防护 + 可扩容）

在 `library-cloud` 目录执行：`docker compose up -d --build`

- **对外主入口（PPT）**：`http://localhost:18888`（Nginx）→ Gateway；与 Postman 直连 `http://localhost:8080` 等价。
- MySQL 数据在命名卷 **`library-cloud-mysql-data`**；库 **`userdb` / `bookdb` / `borrowdb`** 由 `docker/mysql/init/01-databases.sql` 创建。
- MySQL 映射到宿主机端口见 **`env.example` 中 `MYSQL_HOST_PORT`**（默认 **13306**，避免与本机 3306 冲突）。
- **`PUT /api/books/{id}/stock`** 必须带头 **`X-Internal-Token`**（与 compose 环境变量 **`INTERNAL_SERVICE_TOKEN`** 一致）；借阅服务 **Feign 自动带令牌**，直连图书服务无令牌会得到 **403**。
- 网关 **401** 返回 **`application/problem+json`**（RFC 7807）正文。

**Feign 负载均衡（真实多实例）**：`docker compose up -d --scale book-service=2 --no-recreate`，Eureka 中 **BOOK-SERVICE** 应为 2 个实例。

**不用 Docker**：仍可用 `mvn` + H2；`INTERNAL_SERVICE_TOKEN` 默认与两服务 `app.internal.api-token` 已对齐。
